Polymorphism in Java: four types

Polymorphism means one name or one piece of code works with many types. Java gets there in four ways: ad-hoc, inclusion, coercion and parametric.

Ad-hoc polymorphism (overloading)

Methods with the same name act differently for different argument types. Adding two ints gives a number, while the same sum on two Strings joins them.

public class Main {
    public static int sum(int x, int y) {
        int c = x + y;
        return c;
    }

    public static String sum(String x, String y) {
        String joined = x.concat(y);
        return joined;
    }

    public static void main(String[] args) {
        System.out.println(sum(50, 20) + " :- Integer addition Output");
        System.out.println(sum("Polymorphism", " achieved")
                           + " :- String Concatenation Output");
    }
}
70 :- Integer addition Output Polymorphism achieved :- String Concatenation Output
Explain the code line by line
  1. sum(int x, int y) adds two numbers and returns an int.
  2. sum(String x, String y) has the same name but different parameter types, so Java treats it as a separate method. concat appends y to x.
  3. sum(50, 20): both arguments are ints, so the compiler binds the call to the int version. Result 70.
  4. sum("Polymorphism", " achieved"): both are Strings, so the String version runs.
  5. The + " :- ..." after each call is plain String joining, which is itself Java’s one built-in example of ad-hoc polymorphism.
Try it: which sum() runs?
Key points
  • Overloads must differ in the number, type or order of parameters. A different return type alone is not enough.
  • The compiler picks the overload before the program runs, so this is early (static) binding.
  • Java does not let you define your own operators, so the + behaviour is limited to numbers and Strings.

Inclusion polymorphism (subtyping)

Objects of derived classes are used through a base-class reference. JPG, PNG and GIF are all image files, so each is a subclass of an abstract Image that must provide display().

abstract class Image {
    public Image() { }
    abstract void display();
}

class Jpg extends Image {
    public Jpg() { }
    @Override
    void display() { System.out.println("JPG Image File"); }
}

class Png extends Image {
    public Png() { }
    @Override
    void display() { System.out.println("PNG Image File"); }
}

public class Main {
    public static void main(String[] args) {
        Image img;
        Jpg jg = new Jpg();
        Png pg = new Png();

        img = jg;          // reference now holds a Jpg
        img.display();

        img = pg;          // reference now holds a Png
        img.display();
    }
}
JPG Image File PNG Image File
Explain the code line by line
  1. abstract void display(); declares the method with no body. Every concrete subclass must supply one.
  2. Jpg extends Image and Png extends Image each override display() with their own message. @Override makes the compiler verify the override.
  3. Image img; is a reference of the parent type. It can point to any object whose class extends Image.
  4. img = jg; is an implicit upcast. The call img.display() looks identical each time, but the JVM checks the actual object and runs Jpg.display().
  5. After img = pg; the very same call prints the PNG message.

How Java finds the method at run time
  • The compiler only checks that the reference type (Image) has a method called display().
  • At run time the JVM looks at the real object and calls its version. This is dynamic method dispatch, or late binding.
  • The GeeksforGeeks article describes this with C++ virtual functions. In Java every instance method behaves this way by default, so no keyword is needed.

Coercion polymorphism (casting)

A value or object is converted to another type so it can be used where that type is expected. The conversion is implicit when the compiler does it and explicit when you write a cast.

class IntClass {
    private int num;

    public IntClass(int a) { num = a; }

    // converts the user-defined type to a basic type
    public int intValue() { return num; }
}

public class Main {
    public static void show(int x) {
        System.out.println(x);
    }

    public static void main(String[] args) {
        float f = 100;              // implicit: int becomes float
        System.out.println(f);

        IntClass i = new IntClass(100);
        show(746);
        show(i.intValue());         // object converted to int, then passed
    }
}
100.0 746 100
Explain the code line by line
  1. float f = 100; stores an int in a float. The compiler widens it silently, which is implicit coercion.
  2. show(int x) expects an int, so it can take 746 directly.
  3. IntClass is a user-defined type, so it cannot be passed to show as it is.
  4. intValue() converts the IntClass object into the int it holds, and that int is passed to show.
  5. Java has no user-defined conversion operators, so unlike the C++ version this conversion is a method call you write yourself. Java’s own wrapper classes use the same convention, such as Integer.intValue().

Parametric polymorphism (generics)

The same piece of code works for different types. A generic method with a type parameter T finds the greater of two Integers or two Strings without being rewritten.

public class GreaterDemo {
    // works for any type T that knows how to compare itself
    public static <T extends Comparable<T>> T greater(T a, T b) {
        if (a.compareTo(b) > 0) {
            return a;
        } else {
            return b;
        }
    }

    public static void main(String[] args) {
        System.out.println(greater(55, 11));

        String str1 = "Early";
        String str2 = "Binding";
        System.out.println(greater(str1, str2));
    }
}
55 Early
Explain the code line by line
  1. <T extends Comparable<T>> declares a placeholder type T. The bound means T must be comparable with itself, which Integer and String both are.
  2. T greater(T a, T b) takes two values of the same type and returns that type, so no cast is needed by the caller.
  3. The operator > cannot be used on objects, so a.compareTo(b) > 0 asks whether a comes after b.
  4. greater(55, 11): the compiler infers T as Integer, and 55 is returned.
  5. greater(str1, str2): T is String. "Early" comes after "Binding" alphabetically, so "Early" is returned.
Try it: what does the compiler infer for T?
Key points
  • The type is decided at compile time, so a wrong combination is rejected before the program runs.
  • Java generics work with objects, so 55 is boxed to Integer automatically. You cannot write <int>.
  • The bound extends Comparable<T> is what makes compareTo available inside the method.
