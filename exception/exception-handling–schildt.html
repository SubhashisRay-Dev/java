1. Fundamentals

DefinitionAn exception is an abnormal condition that arises in a code sequence at run time, i.e. a run-time error. A Java exception is an object that describes the error; it is created and thrown in the method that caused it. That method can handle it or pass it on, but eventually it is caught and processed.

Exceptions are generated either by the Java run-time system (violating language rules) or manually by your code (to report errors to a method’s caller). Handling is managed by five keywords:

try – code to monitorcatch – handles the exceptionthrow – manually throw onethrows – declares what a method may throwfinally – always runs after try

General form

try {
   // block of code to monitor for errors
}
catch (ExceptionType1 exOb) {
  // exception handler for ExceptionType1
}

catch (ExceptionType2 exOb) {
   // exception handler for ExceptionType2
}
// ...
finally {
   // block of code to be executed after try block ends
}
Fig 1: Flow of try / catch / finally

2. Exception Types

DefinitionAll exception types are subclasses of the built-in class Throwable, the top of the hierarchy. It has two branches: Exception (conditions programs should catch; subclass it for custom exceptions) and Error (run-time environment failures, e.g. stack overflow, not normally caught).

RuntimeException is an important subclass of Exception; it covers things like division by zero and invalid array indexing and is defined automatically for your programs.

3. Uncaught Exceptions

If you do not handle an exception, the default handler of the run-time system prints a description of the exception, a stack trace, and terminates the program.

Program 1 · Exc0
class Exc0 {
  public static void main(String args[]) {
    int d = 0;
    int a = 42 / d;
  }
}
💡 Code help
  • int d = 0; sets up the divisor as zero.
  • int a = 42 / d; critical line: integer division by zero. The run-time creates an ArithmeticException object and throws it.
  • No try/catch exists, so the default handler takes over.
Working
  1. main starts, d = 0.
  2. Line 4 divides 42 by 0 → exception object created and thrown.
  3. No handler in main → default handler prints trace → program stops.
java.lang.ArithmeticException: / by zero
        at Exc0.main(Exc0.java:4)

The trace shows class name Exc0, method main, file Exc0.java and line 4.

Program 2 · Exc1 (error inside another method)
class Exc1 {
  static void subroutine() {
    int d = 0;
    int a = 10 / d;
  }
  public static void main(String args[]) {
    Exc1.subroutine();
  }
}
💡 Code help
  • Exc1.subroutine(); pushes subroutine onto the call stack on top of main.
  • 10 / d throws inside subroutine, so the trace lists both methods.
java.lang.ArithmeticException: / by zero
     at Exc1.subroutine(Exc1.java:4)
     at Exc1.main(Exc1.java:7)

Working: the top line of the trace is where the error happened (line 4); the next line is the caller (main, line 7). The call stack pinpoints the exact sequence of steps that led to the error.

4. Using try and catch

DefinitionA try block encloses code to monitor; a catch clause immediately after it names the exception type it handles. Benefits: you can fix the error and prevent automatic termination.
Program 3 · Exc2
class Exc2 {
  public static void main(String args[]) {
    int d, a;

         try { // monitor a block of code.
           d = 0;
           a = 42 / d;
           System.out.println("This will not be printed.");
         } catch (ArithmeticException e) { // catch divide-by-zero error
           System.out.println("Division by zero.");
         }
         System.out.println("After catch statement.");
    }
}
💡 Code help
  • try { starts the monitored block.
  • a = 42 / d; throws ArithmeticException; control jumps out of try.
  • println("This will not be printed.") is skipped. Control never “returns” to try from catch.
  • catch (ArithmeticException e) matches the thrown type; e holds the exception object.
  • Last println runs normally: execution continues after the whole try/catch.
Working
  1. d = 0 → division throws → try is abandoned.
  2. catch prints “Division by zero.”
  3. Program continues with “After catch statement.”
Division by zero.
After catch statement.
Rules: a try and its catch form a unit; the catch only covers the immediately preceding try; try statements must use curly braces (no single-statement try).
Program 4 · HandleError (handle and move on)
// Handle an exception and move on.
import java.util.Random;

class HandleError {
  public static void main(String args[]) {
      int a=0, b=0, c=0;
      Random r = new Random();

      for(int i=0; i<32000; i++) {
        try {
          b = r.nextInt();
          c = r.nextInt();
          a = 12345 / (b/c);
        } catch (ArithmeticException e) {
          System.out.println("Division by zero.");
          a = 0; // set a to zero and continue
        }
        System.out.println("a: " + a);
      }
  }
}
💡 Code help
  • new Random() + nextInt() give random integers b and c.
  • b/c is zero-division if c = 0; also 12345 / (b/c) fails if b/c becomes 0.
  • a = 0; inside catch sets a safe value so the loop continues as if no error happened.
  • The loop runs 32000 times; the catch keeps it alive.

Working: each iteration tries the division; on ArithmeticException it prints “Division by zero.”, sets a to 0, then prints a.

Displaying a description of an exception

Throwable overrides toString(), so printing the exception object prints its description. The catch block above can be rewritten as:

catch (ArithmeticException e) {
  System.out.println("Exception: " + e);
  a = 0; // set a to zero and continue
}
Exception: java.lang.ArithmeticException: / by zero

5. Multiple catch Clauses

DefinitionOne try can be followed by two or more catch clauses, each for a different exception type. They are checked in order; the first matching one runs and the rest are skipped.
Program 5 · MultiCatch
// Demonstrate multiple catch statements.
class MultiCatch {
  public static void main(String args[]) {
    try {
      int a = args.length;
      System.out.println("a = " + a);
      int b = 42 / a;
      int c[] = { 1 };
      c[42] = 99;
    } catch(ArithmeticException e) {
      System.out.println("Divide by 0: " + e);
    } catch(ArrayIndexOutOfBoundsException e) {
      System.out.println("Array index oob: " + e);
    }
    System.out.println("After try/catch blocks.");
  }
}
💡 Code help
  • args.length = number of command-line arguments.
  • 42 / a throws ArithmeticException when no arguments are given (a = 0).
  • int c[] = { 1 }; array of length 1, so c[42] = 99; throws ArrayIndexOutOfBoundsException.
  • Two catches: only the first matching one executes.
Working
  1. No args: a = 0 → division fails → first catch runs.
  2. One arg: a = 1 → division OK → c[42] fails → second catch runs.
C:\>java MultiCatch
a = 0
Divide by 0: java.lang.ArithmeticException: / by zero
After try/catch blocks.

C:\>java MultiCatch TestArg

Array index oob: java.lang.ArrayIndexOutOfBoundsException:42
After try/catch blocks.
Golden rule: subclasses must come before their superclasses. A superclass catch also catches all its subclasses, so a later subclass catch would be unreachable, and unreachable code is a compile-time error.
Program 6 · SuperSubCatch (compile-time error)
/* This program contains an error.

   A subclass must come before its superclass in
   a series of catch statements. If not,
   unreachable code will be created and a
   compile-time error will result.
*/
class SuperSubCatch {
  public static void main(String args[]) {
    try {
      int a = 0;
      int b = 42 / a;
    } catch(Exception e) {
      System.out.println("Generic Exception catch.");
    }
    /* This catch is never reached because
       ArithmeticException is a subclass of Exception. */
    catch(ArithmeticException e) { // ERROR - unreachable
      System.out.println("This is never reached.");
    }
  }
}
💡 Code help
  • catch(Exception e) already catches every Exception-based error, including ArithmeticException.
  • catch(ArithmeticException e) can never run → compiler reports it as unreachable.
  • Fix: reverse the order of the two catch statements.

6. Nested try Statements

DefinitionA try can sit inside another try. If the inner try has no matching catch, the stack is unwound and the outer try’s catch handlers are checked. If none match, the Java run-time handles it.
Program 7 · NestTry
// An example of nested try statements.
class NestTry {
  public static void main(String args[]) {
    try {
      int a = args.length;

      /* If no command-line args are present,
         the following statement will generate
         a divide-by-zero exception. */
      int b = 42 / a;

      System.out.println("a = " + a);

      try { // nested try block
        /* If one command-line arg is used,
           then a divide-by-zero exception
           will be generated by the following code. */
        if(a==1) a = a/(a-a); // division by zero

        /* If two command-line args are used,
           then generate an out-of-bounds exception. */
        if(a==2) {
          int c[] = { 1 };
          c[42] = 99; // generate an out-of-bounds exception
        }
      } catch(ArrayIndexOutOfBoundsException e) {
        System.out.println("Array index out-of-bounds: " + e);
      }

    } catch(ArithmeticException e) {
      System.out.println("Divide by 0: " + e);
    }
  }
}
💡 Code help
  • int b = 42 / a; in the outer try: fails when no args.
  • a = a/(a-a): with one arg this divides by 0 inside the inner try; the inner catch only handles array errors, so the exception passes outward to the outer ArithmeticException catch.
  • c[42] = 99; with two args is caught by the inner catch.
Working (by number of arguments)
ArgsWhat happens
0Outer 42/a fails → outer catch.
1Prints a = 1; inner division fails; inner catch doesn’t match → outer catch.
2Prints a = 2; inner array error → inner catch.

Nesting can also be implicit through method calls: a try inside a called method is still nested inside the caller’s try.

Program 8 · MethNestTry
/* Try statements can be implicitly nested via
   calls to methods. */
class MethNestTry {
  static void nesttry(int a) {
    try { // nested try block
      /* If one command-line arg is used,
         then a divide-by-zero exception
         will be generated by the following code. */
      if(a==1) a = a/(a-a); // division by zero

      /* If two command-line args are used,
         then generate an out-of-bounds exception. */
      if(a==2) {
        int c[] = { 1 };
        c[42] = 99; // generate an out-of-bounds exception
      }
    } catch(ArrayIndexOutOfBoundsException e) {
      System.out.println("Array index out-of-bounds: " + e);
    }
  }

  public static void main(String args[]) {
    try {
      int a = args.length;

      /* If no command-line args are present,
         the following statement will generate
         a divide-by-zero exception. */
      int b = 42 / a;
      System.out.println("a = " + a);

      nesttry(a);
    } catch(ArithmeticException e) {
      System.out.println("Divide by 0: " + e);
    }
  }
}
💡 Code help
  • nesttry(a); is called from inside main’s try, so nesttry’s try is implicitly nested.
  • An ArithmeticException not caught in nesttry travels back to main’s catch.

Working: the output is identical to Program 7.

7. throw

Definitionthrow ThrowableInstance; explicitly throws an exception. The object must be of type Throwable or a subclass (not int, String, Object…). You get one from a catch parameter or by new.

Execution stops immediately after throw. The nearest enclosing try is checked for a matching catch, then the next, and so on; if none matches, the default handler halts the program.

Program 9 · ThrowDemo
// Demonstrate throw.
class ThrowDemo {
  static void demoproc() {
    try {
      throw new NullPointerException("demo");
    } catch(NullPointerException e) {
      System.out.println("Caught inside demoproc.");
      throw e; // rethrow the exception
    }
  }

  public static void main(String args[]) {
    try {
      demoproc();
    } catch(NullPointerException e) {
      System.out.println("Recaught: " + e);
    }
  }
}
💡 Code help
  • throw new NullPointerException("demo"); builds the object with a message string and throws it.
  • throw e; rethrows the caught exception to the outer handler.
  • The message is shown when the object is printed, or via getMessage().
Working
  1. main’s try calls demoproc().
  2. demoproc throws NPE(“demo”); its own catch prints “Caught inside demoproc.”
  3. It rethrows; main’s catch prints “Recaught: …”.
Caught inside demoproc.
Recaught: java.lang.NullPointerException: demo

8. throws

DefinitionA throws clause in a method declaration lists the exception types the method might throw but does not handle, so callers can guard themselves. Required for all exceptions except Error, RuntimeException and their subclasses.
type method-name(parameter-list) throws exception-list
{
  // body of method
}
Program 10 · ThrowsDemo (will not compile)
// This program contains an error and will not compile.
class ThrowsDemo {
  static void throwOne() {
    System.out.println("Inside throwOne.");
    throw new IllegalAccessException("demo");
  }
  public static void main(String args[]) {
    throwOne();
  }
}

Two fixes needed: declare throws IllegalAccessException and catch it in main.

Program 10 (corrected)
// This is now correct.
class ThrowsDemo {
  static void throwOne() throws IllegalAccessException {
    System.out.println("Inside throwOne.");
    throw new IllegalAccessException("demo");
  }
  public static void main(String args[]) {
    try {
      throwOne();
    } catch (IllegalAccessException e) {
      System.out.println("Caught " + e);
    }
  }
}
💡 Code help
  • throws IllegalAccessException declares the checked exception.
  • The try/catch in main handles it. Without it, main would also need its own throws.
inside throwOne
caught java.lang.IllegalAccessException: demo

9. finally

DefinitionThe finally block runs after a try/catch completes, whether or not an exception is thrown, even if no catch matches, and even before a return. Ideal for closing files and freeing resources. It is optional, but every try needs at least one catch or a finally.
Program 11 · FinallyDemo
// Demonstrate finally.
class FinallyDemo {
  // Through an exception out of the method.
  static void procA() {
    try {
      System.out.println("inside procA");
      throw new RuntimeException("demo");
    } finally {
      System.out.println("procA's finally");
    }
  }

  // Return from within a try block.
  static void procB() {
    try {
      System.out.println("inside procB");
      return;
    } finally {
      System.out.println("procB's finally");
    }
  }
 // Execute a try block normally.
  static void procC() {
    try {
      System.out.println("inside procC");
    } finally {
      System.out.println("procC's finally");
    }
  }

  public static void main(String args[]) {
    try {
      procA();
    } catch (Exception e) {
      System.out.println("Exception caught");
    }
    procB();
    procC();
  }
}
💡 Code help
  • procA: throw new RuntimeException leaves the try abruptly, but finally still runs “on the way out”; main’s catch then handles it.
  • procB: return; exits the method, yet finally runs just before returning.
  • procC: normal completion; finally still runs.
Working
  1. procA prints “inside procA”, throws; finally prints; exception goes to main → “Exception caught”.
  2. procB prints, hits return; finally prints; returns.
  3. procC prints, then finally prints.

11. Creating Your Own Exception Subclasses

DefinitionA custom exception is a subclass of Exception. It need not implement anything: its existence in the type system lets you use it as an exception. It inherits all Throwable methods (Table 10-3).

Table 10-3 · Methods defined by Throwable

MethodDescription
Throwable fillInStackTrace( )Returns a Throwable with a completed stack trace; can be rethrown.
Throwable getCause( )Returns the underlying exception, or null.
String getLocalizedMessage( )Returns a localized description.
String getMessage( )Returns a description of the exception.
StackTraceElement[ ] getStackTrace( )Returns the stack trace as an array; first element is the last method called.
Throwable initCause(Throwable causeExc)Associates causeExc as the cause; returns a reference to the exception.
void printStackTrace( )Displays the stack trace.
void printStackTrace(PrintStream / PrintWriter stream)Sends the stack trace to the specified stream.
void setStackTrace(StackTraceElement elements[ ])Sets the stack trace (specialized use).
String toString( )Returns a description; called by println( ).

Constructors: Exception( ) (no description) and Exception(String msg). Overriding toString( ) lets you drop the default “name: ” prefix for cleaner output.

Program 12 · MyException / ExceptionDemo
// This program creates a custom exception type.
class MyException extends Exception {
  private int detail;

  MyException(int a) {
    detail = a;
  }

  public String toString() {
    return "MyException[" + detail + "]";
  }
}

class ExceptionDemo {
  static void compute(int a) throws MyException {
    System.out.println("Called compute(" + a + ")");
    if(a > 10)
      throw new MyException(a);
    System.out.println("Normal exit");
  }

  public static void main(String args[]) {
    try {
      compute(1);
      compute(20);
    } catch (MyException e) {
      System.out.println("Caught " + e);
    }
  }
}
💡 Code help
  • class MyException extends Exception creates the custom checked exception.
  • private int detail; stores the offending value.
  • toString() override returns MyException[detail], controlling what println shows.
  • throws MyException on compute declares it; if(a > 10) throw new MyException(a); raises it.
Working
  1. compute(1): prints “Called compute(1)”, 1 is not > 10, prints “Normal exit”.
  2. compute(20): prints “Called compute(20)”, 20 > 10 → throws MyException(20).
  3. main’s catch prints “Caught ” + e, which calls our toString().
Called compute(1)
Normal exit
Called compute(20)
Caught MyException[20]

12. Chained Exceptions (JDK 1.4+)

DefinitionChained exceptions let you attach a second exception, the cause, to an exception. Example: an ArithmeticException is thrown, but the real reason was an I/O error that set the divisor wrongly.

Throwable constructors: Throwable(Throwable causeExc) and Throwable(String msg, Throwable causeExc) (also in Error, Exception, RuntimeException). Methods: Throwable getCause( ) and Throwable initCause(Throwable causeExc). The cause can be set only once: not with initCause if a constructor already set it.

Program 13 · ChainExcDemo
// Demonstrate exception chaining.
class ChainExcDemo {
  static void demoproc() {
    // create an exception
    NullPointerException e =
      new NullPointerException("top layer");

    // add a cause
    e.initCause(new ArithmeticException("cause"));

    throw e;
  }

  public static void main(String args[]) {
    try {
      demoproc();
    } catch(NullPointerException e) {
      // display top level exception
      System.out.println("Caught: " + e);

      // display cause exception
      System.out.println("Original cause: " +
                          e.getCause());
    }
  }
}
💡 Code help
  • new NullPointerException("top layer") is the top-level exception.
  • e.initCause(new ArithmeticException("cause")); attaches the underlying cause.
  • throw e; sends the whole chain out of demoproc.
  • e.getCause() in main retrieves the ArithmeticException.
Caught: java.lang.NullPointerException: top layer
Original cause: java.lang.ArithmeticException: cause

Chains can go to any depth, but overly long chains may indicate poor design.

13. Using Exceptions

  • Think of try, throw and catch as clean ways to handle errors and unusual boundary conditions. When a method can fail, have it throw an exception instead of returning error codes.
  • Do not use exception handling as a general mechanism for non-local branching; it confuses code and hurts maintainability.
