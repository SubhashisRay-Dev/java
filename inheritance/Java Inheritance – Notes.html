1. Inheritance Basics

DefinitionInheritance allows hierarchical classification. A general class (the superclass) defines common traits; a more specific class (the subclass) inherits all its instance variables and methods and adds its own. Use the extends keyword.
class subclass-name extends superclass-name {
  // body of class
}
Fig 1: A multilevel hierarchy (see section 7)
Program 1 · SimpleInheritance
// A simple example of inheritance.

// Create a superclass.
class A {
  int i, j;

  void showij() {
    System.out.println("i and j: " + i + " " + j);
  }
}

// Create a subclass by extending class A.
class B extends A {
  int k;

  void showk() {
    System.out.println("k: " + k);
  }
  void sum() {
    System.out.println("i+j+k: " + (i+j+k));
  }
}

class SimpleInheritance {
  public static void main(String args[]) {
    A superOb = new A();
    B subOb = new B();

    // The superclass may be used by itself.
    superOb.i = 10;
    superOb.j = 20;
    System.out.println("Contents of superOb: ");
    superOb.showij();
    System.out.println();

    /* The subclass has access to all public members of
       its superclass. */
    subOb.i = 7;
    subOb.j = 8;
    subOb.k = 9;
    System.out.println("Contents of subOb: ");
    subOb.showij();
    subOb.showk();
    System.out.println();

    System.out.println("Sum of i, j and k in subOb:");
    subOb.sum();
  }
}
Contents of superOb:
i and j: 10 20

Contents of subOb:
i and j: 7 8
k: 9

Sum of i, j and k in subOb:
i+j+k: 24

B includes all members of A, so subOb can use i, j and showij(), and sum() uses i and j directly. A is still an independent class, and a subclass can itself be a superclass.

Rules: only one superclass per subclass (no multiple inheritance of classes); a hierarchy of any depth is fine; no class can be a superclass of itself.

2. Member Access and Inheritance

DefinitionA subclass includes all members of its superclass, but it cannot access members declared private in the superclass.
Program 2 · Access (will not compile)
/* In a class hierarchy, private members remain
   private to their class.

   This program contains an error and will not
   compile.
*/

// Create a superclass.
class A {
  int i; // public by default
  private int j; // private to A

  void setij(int x, int y) {
    i = x;
    j = y;
  }
}

// A's j is not accessible here.
class B extends A {
  int total;
  void sum() {
    total = i + j; // ERROR, j is not accessible here
  }
}

class Access {
  public static void main(String args[]) {
    B subOb = new B();

    subOb.setij(10, 12);

    subOb.sum();
    System.out.println("Total is " + subOb.total);
  }
}

The reference to j inside sum() of B is an access violation: private members are accessible only inside their own class.

REMEMBER: a private member remains private to its class. It is not accessible by any code outside its class, including subclasses.

3. A More Practical Example (Box → BoxWeight)

Box (width, height, depth) is extended with a fourth component, weight.

Program 3 · DemoBoxWeight
// This program uses inheritance to extend Box.
class Box {
  double width;
  double height;
  double depth;

  // construct clone of an object
  Box(Box ob) { // pass object to constructor
    width = ob.width;
    height = ob.height;
    depth = ob.depth;
  }

  // constructor used when all dimensions specified
  Box(double w, double h, double d) {
    width = w;
    height = h;
    depth = d;
  }

  // constructor used when no dimensions specified
  Box() {
    width = -1; // use -1 to indicate
    height = -1; // an uninitialized
    depth = -1; // box
  }

  // constructor used when cube is created
  Box(double len) {
    width = height = depth = len;
  }

  // compute and return volume
  double volume() {
    return width * height * depth;
  }
}

// Here, Box is extended to include weight.
class BoxWeight extends Box {
  double weight; // weight of box

  // constructor for BoxWeight
  BoxWeight(double w, double h, double d, double m) {
    width = w;
    height = h;
    depth = d;
    weight = m;
  }
}

class DemoBoxWeight {
  public static void main(String args[]) {
    BoxWeight mybox1 = new BoxWeight(10, 20, 15, 34.3);
    BoxWeight mybox2 = new BoxWeight(2, 3, 4, 0.076);
    double vol;

    vol = mybox1.volume();
    System.out.println("Volume of mybox1 is " + vol);
    System.out.println("Weight of mybox1 is " + mybox1.weight);
    System.out.println();

    vol = mybox2.volume();
    System.out.println("Volume of mybox2 is " + vol);
    System.out.println("Weight of mybox2 is " + mybox2.weight);
  }
}
Volume of mybox1 is 3000.0
Weight of mybox1 is 34.3

Volume of mybox2 is 24.0
Weight of mybox2 is 0.076

BoxWeight need not re-create Box’s features. Once a superclass defines common attributes, any number of specialised subclasses can be built from it, for example:

// Here, Box is extended to include color.
class ColorBox extends Box {
  int color; // color of box

  ColorBox(double w, double h, double d, int c) {
    width = w;
    height = h;
    depth = d;
    color = c;
  }
}

4. A Superclass Variable Can Reference a Subclass Object

DefinitionA reference variable of a superclass can be assigned a reference to any subclass object. The type of the reference variable (not the object) decides which members can be accessed.
Fig 2: Box reference to a BoxWeight object
Program 4 · RefDemo
class RefDemo {
  public static void main(String args[]) {
    BoxWeight weightbox = new BoxWeight(3, 5, 7, 8.37);
    Box plainbox = new Box();
    double vol;

    vol = weightbox.volume();
    System.out.println("Volume of weightbox is " + vol);
    System.out.println("Weight of weightbox is " +
                       weightbox.weight);
    System.out.println();

    // assign BoxWeight reference to Box reference
    plainbox = weightbox;

    vol = plainbox.volume(); // OK, volume() defined in Box
    System.out.println("Volume of plainbox is " + vol);

    /* The following statement is invalid because plainbox
       does not define a weight member. */
//  System.out.println("Weight of plainbox is " + plainbox.weight);
  }
}

Because the superclass has no knowledge of what a subclass adds, plainbox cannot see weight, so that line is commented out. (The book prints no output for this program.)

5. Using super

Definitionsuper refers to the immediate superclass. It has two forms: (1) super(arg-list); calls a superclass constructor, and (2) super.member accesses a superclass member hidden by a subclass member.

5.1 super() to call superclass constructors

Duplicating Box’s initialisation in BoxWeight is inefficient and needs access to Box’s data. If Box makes its data private, a subclass can only initialise it via super(arg-list), which must be the first statement in the subclass constructor.

// BoxWeight now uses super to initialize its Box attributes.
class BoxWeight extends Box {
  double weight; // weight of box

  // initialize width, height, and depth using super()
  BoxWeight(double w, double h, double d, double m) {
    super(w, h, d); // call superclass constructor
    weight = m;
  }
}

Since constructors can be overloaded, super() can use any form defined by the superclass; the one matching the arguments runs. Below, width, height and depth are now private.

Pay special attention to the clone constructor. super(ob) is passed a BoxWeight, yet it invokes Box(Box ob), because a superclass variable can reference a subclass object:

// construct clone of an object
BoxWeight(BoxWeight ob) { // pass object to constructor
  super(ob);
  weight = ob.weight;
}
Key points: super() always refers to the superclass immediately above the calling class (even in a multilevel hierarchy) and must be the first statement in the subclass constructor.

5.2 A second use for super: super.member

Acts like this, but always refers to the superclass. Useful when a subclass member hides a superclass member of the same name.

Program 6 · UseSuper
// Using super to overcome name hiding.
class A {
  int i;
}

// Create a subclass by extending class A.
class B extends A {
  int i; // this i hides the i in A

  B(int a, int b) {
    super.i = a; // i in A
    i = b; // i in B
  }

  void show() {
    System.out.println("i in superclass: " + super.i);
    System.out.println("i in subclass: " + i);
  }
}

class UseSuper {
  public static void main(String args[]) {
    B subOb = new B(1, 2);

    subOb.show();
  }
}
i in superclass: 1
i in subclass: 2

super can also call methods that are hidden by a subclass.

DefinitionA subclass can be the superclass of another: if C extends B and B extends A, then C inherits all traits of B and A. Here BoxWeight becomes the superclass of Shipment, which adds cost.

7. When Constructors Are Called

DefinitionIn a class hierarchy, constructors are called in order of derivation, from superclass to subclass. Since super() is the first statement, this holds whether or not it is written. If it is omitted, the default (parameterless) constructor of each superclass runs.
Fig 3: Constructor call order

  }
}

// Create a subclass by extending class A.
class B extends A {
  B() {
    System.out.println("Inside B's constructor.");
  }
}

// Create another subclass by extending B.
class C extends B {
  C() {
    System.out.println("Inside C's constructor.");
  }
}

class CallingCons {

  }

Inside B’s constructor
Inside C’s constructor

This makes sense: a superclass has no knowledge of any subclass, so its initialisation is separate from, and possibly prerequisite to, the subclass’s.

8. Method Overriding

DefinitionWhen a subclass method has the same name and type signature as a superclass method, it overrides it. Calls from the subclass always use the subclass version; the superclass version is hidden.
Program 9 · Override
// Method overriding.
class A {
  int i, j;
  A(int a, int b) {
    i = a;
    j = b;
  }

  // display i and j
  void show() {
    System.out.println("i and j: " + i + " " + j);
  }
}

class B extends A {
  int k;

  B(int a, int b, int c) {
    super(a, b);
    k = c;
  }

  // display k – this overrides show() in A
  void show() {
    System.out.println("k: " + k);
  }
}

class Override {
  public static void main(String args[]) {
    B subOb = new B(1, 2, 3);

    subOb.show(); // this calls show() in B
  }
}
k: 3

To reach the superclass version of an overridden method, use super. This version of B displays all instance variables:

class B extends A {
  int k;

  B(int a, int b, int c) {
    super(a, b);
    k = c;
  }
  void show() {
    super.show(); // this calls A's show()
    System.out.println("k: " + k);
  }
}
i and j: 1 2
k: 3
Overriding occurs only when names and type signatures are identical. Otherwise the methods are simply overloaded.
Program 10 · Overloading, not overriding
// Methods with differing type signatures are overloaded – not
// overridden.
class A {
  int i, j;

  A(int a, int b) {
    i = a;
    j = b;
  }

  // display i and j
  void show() {
    System.out.println("i and j: " + i + " " + j);
  }
}

// Create a subclass by extending class A.
class B extends A {
  int k;

  B(int a, int b, int c) {
    super(a, b);
    k = c;
  }

  // overload show()
  void show(String msg) {
    System.out.println(msg + k);
  }
}

class Override {
  public static void main(String args[]) {
    B subOb = new B(1, 2, 3);

    subOb.show("This is k: "); // this calls show() in B
    subOb.show(); // this calls show() in A
  }
}
This is k: 3
i and j: 1 2

B’s show(String msg) has a different signature from A’s show(), so no overriding (or name hiding) takes place; it just overloads.

9. Dynamic Method Dispatch

DefinitionDynamic method dispatch is the mechanism by which a call to an overridden method is resolved at run time, not compile time. It is how Java implements run-time polymorphism. It is the type of the object being referred to (not the type of the reference variable) that decides which version runs.
Fig 4: One reference, three behaviours
Program 11 · Dispatch
// Dynamic Method Dispatch
class A {
  void callme() {
    System.out.println("Inside A's callme method");
  }
}

class B extends A {
  // override callme()
  void callme() {
    System.out.println("Inside B's callme method");
  }
}

class C extends A {
  // override callme()
  void callme() {
    System.out.println("Inside C's callme method");
  }
}

class Dispatch {
  public static void main(String args[]) {
    A a = new A(); // object of type A
    B b = new B(); // object of type B
    C c = new C(); // object of type C
    A r; // obtain a reference of type A

    r = a; // r refers to an A object
    r.callme(); // calls A's version of callme

    r = b; // r refers to a B object
    r.callme(); // calls B's version of callme

    r = c; // r refers to a C object
    r.callme(); // calls C's version of callme
  }
}
Inside A’s callme method
Inside B’s callme method
Inside C’s callme method

Had the version been decided by the type of r, you would see three calls to A’s callme().

NOTE: overridden methods in Java are similar to virtual functions in C++ and C#.

Why overridden methods?

They support run-time polymorphism (“one interface, multiple methods”): a general class specifies methods common to all its derivatives, while subclasses define the specific implementation. Superclass and subclasses form a hierarchy from lesser to greater specialisation; combined with overriding, the superclass defines the general form of the methods used by all its subclasses. Existing code can call methods on instances of new classes without recompiling.

10. Applying Method Overriding

A superclass Figure stores dimensions and defines area(); subclasses Rectangle and Triangle override it.

Program 12 · FindAreas
// Using run-time polymorphism.
class Figure {
  double dim1;
  double dim2;

  Figure(double a, double b) {
    dim1 = a;
    dim2 = b;
  }

  double area() {
    System.out.println("Area for Figure is undefined.");
    return 0;
  }
}

class Rectangle extends Figure {
  Rectangle(double a, double b) {
    super(a, b);
  }

  // override area for rectangle
  double area() {
    System.out.println("Inside Area for Rectangle.");
    return dim1 * dim2;
  }
}

class Triangle extends Figure {
  Triangle(double a, double b) {
    super(a, b);
  }

  // override area for right triangle
  double area() {
    System.out.println("Inside Area for Triangle.");
    return dim1 * dim2 / 2;
  }
}

class FindAreas {
  public static void main(String args[]) {
    Figure f = new Figure(10, 10);
    Rectangle r = new Rectangle(9, 5);
    Triangle t = new Triangle(10, 8);

    Figure figref;

    figref = r;
    System.out.println("Area is " + figref.area());

    figref = t;
    System.out.println("Area is " + figref.area());

    figref = f;
    System.out.println("Area is " + figref.area());
  }
}
Inside Area for Rectangle.
Area is 45
Inside Area for Triangle.
Area is 40
Area for Figure is undefined.
Area is 0

One consistent interface (area()) works for several related types of objects.

11. Using Abstract Classes

DefinitionAn abstract method has no body and must be overridden by subclasses: abstract type name(parameter-list);. Any class with an abstract method must itself be declared abstract. An abstract class cannot be instantiated with new, but you can create references to it.
  • No abstract constructors and no abstract static methods.
  • A subclass must implement all abstract methods, or be declared abstract itself.
  • Abstract classes may also contain concrete methods.
Program 13 · AbstractDemo
// A Simple demonstration of abstract.
abstract class A {
  abstract void callme();

  // concrete methods are still allowed in abstract classes
  void callmetoo() {
    System.out.println("This is a concrete method.");
  }
}

class B extends A {
  void callme() {
    System.out.println("B's implementation of callme.");
  }
}

class AbstractDemo {
  public static void main(String args[]) {
    B b = new B();

    b.callme();
    b.callmetoo();
  }
}

No objects of class A are declared; abstract classes cannot be instantiated but can hold as much implementation as needed.

Program 14 · AbstractAreas (Figure made abstract)
// Using abstract methods and classes.
abstract class Figure {
  double dim1;
  double dim2;

  Figure(double a, double b) {
    dim1 = a;
    dim2 = b;
  }

  // area is now an abstract method
  abstract double area();
}

class Rectangle extends Figure {
  Rectangle(double a, double b) {
    super(a, b);
  }

  // override area for rectangle
  double area() {
    System.out.println("Inside Area for Rectangle.");
    return dim1 * dim2;
  }
}

class Triangle extends Figure {
  Triangle(double a, double b) {
    super(a, b);
  }

  // override area for right triangle
  double area() {
    System.out.println("Inside Area for Triangle.");
    return dim1 * dim2 / 2;
  }
}

class AbstractAreas {
  public static void main(String args[]) {
    // Figure f = new Figure(10, 10); // illegal now
    Rectangle r = new Rectangle(9, 5);
    Triangle t = new Triangle(10, 8);
    Figure figref; // this is OK, no object is created

    figref = r;
    System.out.println("Area is " + figref.area());

    figref = t;
    System.out.println("Area is " + figref.area());
  }
}

Objects of type Figure can no longer be created, and every subclass must override area() (otherwise a compile-time error). A reference of type Figure is fine and is what enables run-time dispatch.

12. Using final with Inheritance

final has three uses: a named constant (previous chapter), and two for inheritance:

12.1 final prevents overriding

class A {
  final void meth() {
    System.out.println("This is a final method.");
  }
}

class B extends A {
  void meth() { // ERROR! Can't override.
    System.out.println("Illegal!");
  }
}

A final method cannot be overridden (compile-time error). Final methods can be inlined by the compiler. Normal calls are resolved at run time (late binding); calls to final methods are resolved at compile time (early binding).

12.2 final prevents inheritance

final class A {
  // ...
}

// The following class is illegal.
class B extends A { // ERROR! Can't subclass A
  // ...
}

Declaring a class final implicitly makes all its methods final. A class cannot be both abstract and final, since an abstract class relies on subclasses to complete it.

13. The Object Class

DefinitionObject is the special class that is the superclass of all other classes. An Object reference can refer to any object (and any array).
MethodPurpose
Object clone( )Creates a new object the same as the one being cloned.
boolean equals(Object object)Determines whether one object is equal to another.
void finalize( )Called before an unused object is recycled.
Class getClass( )Obtains the class of an object at run time.
int hashCode( )Returns the hash code of the invoking object.
void notify( )Resumes a thread waiting on the invoking object.
void notifyAll( )Resumes all threads waiting on the invoking object.
String toString( )Returns a string that describes the object.
void wait( ) / wait(long milliseconds) / wait(long milliseconds, int nanoseconds)Waits on another thread of execution.

getClass(), notify(), notifyAll() and wait() are final; the others may be overridden. equals() compares contents (equality definition varies by type). toString() describes the object and is called automatically by println(); many classes override it.
